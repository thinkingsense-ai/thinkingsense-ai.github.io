Deploy OmniGate to Google Cloud, no local tools required

One guided script in Cloud Shell brings up a right-sized Google Kubernetes Engine cluster (Ampere/arm64 nodes, matching the published image), a seeded Postgres demo backend, and OmniGate itself. Nothing to build, nothing to push: the stack pulls a pre-built image from our own public registry.

View the stack ↓

Opens Cloud Shell with the repo pre-cloned and the deploy tutorial already queued up. You'll need your own GCP project with billing enabled — start a free trial if you don't have one yet.

What actually happens

One script, all in the browser

No Terraform, Docker, or kubectl on your machine for this path — Cloud Shell already has all of them, and a single guided script drives the whole deploy.

1

Sign in to your project

The button opens Cloud Shell with the repo already cloned, and prompts you to pick a GCP project if one isn't set yet.

2

Run the guided script

cd omnigategkestack && ./setup.sh — one script, not a form to hand-fill. It enables the required APIs for you along the way.

3

Answer four prompts

Project/region (defaulted for you), an Ask-app login, and an Anthropic API key — technically optional (the stack deploys fine without one), but the Ask app can't answer any question until it's set, so grab a free key from console.anthropic.com before you start.

4

Confirm the plan

The script runs terraform apply for you and shows exactly what it's about to create — type yes to proceed.

5

Wait for it to finish

Roughly 10–15 minutes: the GKE cluster and node pool, then the OmniGate + Postgres Helm release.

6

Open the Ask app

The script prints the kubectl credentials command at the end. Run kubectl get svc omnigate-omnigate-http, open the LoadBalancer IP on port 8080, and sign in with the login you set in step 3.

Before you run the script

Project prerequisites

Confirmed live while building this stack — worth checking first, especially on a fresh project.

ResourceNeededWhere to check
BillingA billing account linked to the projectgcloud billing projects describe <project>
APIsKubernetes Engine, Compute Engine, Artifact Registrysetup.sh enables these for you automatically
ComputeT2A (Ampere/arm64) — 2 vCPU / 8GB by defaultService compute.googleapis.com, quota metric T2A_CPUS in your target region

Node count and machine type are adjustable in terraform.tfvars if your project has more headroom — or less. The published image is arm64-only, so any replacement machine type needs to stay on an arm64 (T2A) family.

Prefer the CLI

Same stack, from your terminal

Useful for scripting a deploy, or if you'd rather review the plan yourself before anything gets created. Needs gcloud, terraform, curl, python3, and a JRE installed locally.

1

Clone and authenticate

Same repo Cloud Shell would clone for you.

git clone https://github.com/thinkingsense-ai/Docker.git
cd Docker/resource-manager/omnigategkestack
gcloud auth login
gcloud auth application-default login
2

Run the guided script, or drive Terraform directly

Same script Cloud Shell runs — or skip it and fill terraform.tfvars by hand.

# guided
./setup.sh

# or, by hand
cp terraform.tfvars.example terraform.tfvars
terraform init && terraform apply
Ask-app login: just type a plain username and password when prompted — omnigate_app_password is hashed automatically during apply, using the deployed image's own hashing utility. No local Docker, no manual hash generation. Full details in the stack's README.
