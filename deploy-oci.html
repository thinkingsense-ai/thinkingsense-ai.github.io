Deploy OmniGate to Oracle Cloud, no local tools required

A schema-driven OCI Resource Manager stack brings up a right-sized Oracle Kubernetes Engine cluster, a seeded Postgres demo backend, and OmniGate itself — entirely from your browser. Nothing to build, nothing to push: the stack pulls a pre-built image from our own public registry.

Download the zip ↓

Opens the OCI Console's Create Stack wizard, pre-loaded from our published Resource Manager stack. You'll need your own OCI tenancy — sign up for Always Free if you don't have one yet.

What actually happens

Six steps, all in the browser

No Terraform, Docker, or kubectl on your machine for this path — Resource Manager runs the provisioning inside Oracle-managed infrastructure.

1

Sign in to your tenancy

The Deploy button takes you to OCI Console sign-in. New to OCI? The Always Free tier covers everything this stack defaults to.

2

Create Stack, pre-loaded

Console lands on Create Stack with the Terraform source already set to our published zip — fetched server-side, nothing to upload yourself.

3

Fill in the wizard

A guided form, not a raw variable dump — compartment and region, an Ask-app login, and (optionally) an Anthropic API key for NL2SQL, grouped exactly like the local docker-compose.yml options.

4

Create the stack

This only saves your configuration — nothing is provisioned yet.

5

Terraform Actions → Apply

The real provisioning step. Takes roughly 12–15 minutes: the OKE cluster (~8 min), the node pool (~3 min), then the OmniGate + Postgres Helm release.

6

Open the Ask app

The stack's Outputs tab shows ask_app_url — open it, sign in with the login you set in step 3, and ask a real question.

Before you click Apply

Tenancy prerequisites

Confirmed live while building this stack — worth checking under Governance & Administration → Limits, Quotas and Usage first, especially on a fresh or Always-Free tenancy.

ResourceNeededWhere to check
OKE cluster1 basic cluster of quota headroomService container-engine, limit cluster-count
Network Load Balancer1 flexible NLB (2 if you enable wire-protocol exposure)Service lbaas, limit max-nlb-flexible-count

Node count, OCPUs, memory, and storage sizes are all adjustable in the wizard if your tenancy has more headroom — or less.

Prefer the CLI

Same stack, from your terminal

Useful for scripting a deploy, or if you'd rather review the plan before Console ever gets involved.

1

Create the stack

Pulls the same published Terraform config.

oci resource-manager stack create \
  --compartment-id <compartment-ocid> \
  --config-source https://github.com/thinkingsense-ai/Docker/releases/download/oke-stack-v1.1.0/omnigateokestack-v1.1.0.zip \
  --display-name omnigateokestack \
  --variables '{"compartment_ocid":"<ocid>","region":"<region>","omnigate_app_password":"<plain-text-password>"}'
2

Apply it

Auto-approves the plan and provisions everything.

oci resource-manager job create-apply-job \
  --stack-id <stack-ocid> \
  --execution-plan-strategy AUTO_APPROVED
Ask-app login: just type a plain username and password in the wizard — omnigate_app_password is hashed automatically during Apply, using the deployed image's own hashing utility. No local Docker, no manual hash generation. Full details in the stack's README.
