Run OmniGate with Docker

The fastest way to try the free edition: clone the public recipe, run one command, and Docker Compose brings up OmniGate, a demo Postgres and the small local models together. No cloud account needed.

Start in four steps ↓ View the repo on GitHub ↗

Want it on a cloud with a public address instead? See the one-click guides for Oracle Cloud, AWS, Google Cloud and Azure.

Before you start

What you need

ItemNeeded
DockerDocker Desktop (Mac, Windows) or Docker Engine with the Compose plugin (Linux), running
GitTo clone the public recipe
Disk and timeThe first run builds the images and downloads the small local models, so allow several GB of disk and a good while on a first run. Later starts take seconds.
Free ports8080 (the app) plus the demo database ports the recipe publishes, such as 5433, 5442 and 3306. If one is taken, stop what is using it or change the left-hand number in docker-compose.yml.
Anthropic API keyOptional for a first look; needed for plain-English questions to be answered by a cloud model
What actually happens

Four steps

1

Get the recipe

The Docker repository holds the Compose file and the build recipe. It is public; no source access is needed.

git clone https://github.com/thinkingsense-ai/Docker.git
cd Docker
2

Add your Anthropic key (optional)

Put it in an .env file next to docker-compose.yml, or export it in your shell. Skip this to look around first and add it later.

echo "OMNIGATE_LLM_API_KEY=<your key>" > .env
3

Start everything

This builds the images and starts OmniGate, a demo Postgres and the local model services. The first run is the slow one.

docker compose up --build
4

Open the Ask app and the admin console

When the logs settle, open these in your browser. The Ask app signs in as demo / demo.

# business-user Ask app
open http://localhost:8080/
# admin console
open http://localhost:8080/admin

The Ask app's first screen offers five trusted questions about the demo supply-chain data. A small helper container approves them once OmniGate is up, then exits, which is normal.

Connect your own database next: see Docs & setup for pointing OmniGate at a Postgres of yours and the key settings, and the Admin & Ask guide for what to do in each screen.

Before you share it

This quick start has no admin login

The Compose file is a try-it-on-your-laptop configuration: the admin console at /admin opens without a login. That is fine on your own machine. Do not expose the port to a network or the internet until you set admin logins with OMNIGATE_AUTH_USERS (see the repository README). The one-click cloud stacks are secure by default and can also limit which addresses can reach them, so they are the better choice for anything shared.

The free edition

What the free edition includes

Up to 100 connections, 3 data sources, one question in flight at a time, 8 join threads and a single node. That is plenty for evaluating on your own data. For more, contact us about a commercial license, which switches a running deployment over without a rebuild.

Alternative

A ready-made image for ARM machines

If you only want the application itself (for example on an ARM server or an Apple-silicon Mac) and will bring your own database, a pre-built arm64-only image is published in our public Oracle registry. It does not include the demo database or the local models, and it is not built for Intel/AMD machines.

docker pull ocir.us-phoenix-1.oci.oraclecloud.com/ax8tpjdxhykk/omnigate:v0.10.10

Most people should use the Compose route above, which works on both architectures and wires everything together for you.
