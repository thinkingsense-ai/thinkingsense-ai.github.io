Deploy ThinkingSense to Microsoft Azure, no local tools required

ThinkingSense is a governed ontology platform for the enterprise. A form-driven Bicep/ARM template brings up a right-sized AKS cluster running ThinkingSense, with its federated query engine, the Ask App, and a seeded Postgres demo backend, entirely from your browser. Nothing to build, nothing to push: the stack pulls a pre-built image from our own public registry.

Download the template ↓

Opens the Azure Portal's Custom Deployment wizard, pre-loaded from our published Bicep/ARM template. You'll need your own Azure subscription — a free account covers everything this stack defaults to (Ampere Altra quota permitting — see Prerequisites).

What gets deployed

One request, three hops

An Ask App request hits a public Azure Load Balancer, which routes into the AKS cluster to the omnigate pod. omnigate in turn queries the seeded postgres pod over JDBC — that's the whole federated-query path.

What actually happens

Five steps, all in the browser

No Terraform, Docker, or kubectl on your machine for this path — Azure Resource Manager runs the provisioning inside Azure-managed infrastructure, including the Helm install itself (via a deployment script, ARM's answer to a Lambda-backed custom resource).

1

Sign in to your subscription

The Deploy button takes you to Azure Portal sign-in. New to Azure? The free-tier account covers everything this stack defaults to, Ampere Altra regional quota permitting.

2

Custom deployment, pre-loaded

Portal lands on Custom deployment with the template and its form already set to our published release — fetched server-side, nothing to upload yourself.

3

Fill in the wizard

A guided form, not a raw parameters JSON — name a new resource group (the wizard requires "Create new," so this deployment can never end up sharing a resource group with anything else), pick a region, an Ask-app login, and an Anthropic API key. That key is technically optional (the stack deploys fine without one), but the Ask app can't answer any question until it's set, so grab a free key from console.anthropic.com before you start. You can also change it later in the app's Admin console under Models.

4

Review + create

The real provisioning step. Takes roughly 15–20 minutes: the AKS cluster dominates, then the deployment script's Helm install of ThinkingSense + Postgres.

5

Open the Ask app

The deployment's Outputs tab shows askAppUrl — open it, sign in with the login you set in step 3, and ask a real question.

It opens on HTTPS. The first time, your browser will say the certificate is not trusted, because the stack makes its own: choose Advanced, then continue to the site. The connection is encrypted either way; to remove the warning, give the stack your own certificate in the deploy form (Your own certificate).

Choose the demo data. A new install is seeded with all-packs by default: every pack at once (supply chain, manufacturing, IT and operational risk, BOM, Treasury and the Smithsonian sample), with a picker in the Ask app. To start with just one, set the Demo data choice in the deployment wizard (Advanced step): supply-chain, it-risk (IT and operational risk at a financial firm), bom (manufacturing bill of materials and sourcing) or treasury (cash, payables, hedges and debt across two systems). Each comes with approved questions to try. The choice is read on a fresh install only, so changing it later does not reseed; all-packs is the heaviest and needs the most memory and outbound access to GitHub and Hugging Face (on AWS the default node size ran it, with little headroom; it has not yet been run on Azure as the default). All of the data is invented. See what is in each set, with example questions and a first-ten-minutes walkthrough.
Add Agency (optional). Tick Install Agency beside the Ask app on the Advanced step (installAgency in Bicep); its address is the agencyUrl output. Agency is a second front end for risk management that sits beside the Ask app, with its own address and the same logins. It adds the IT-risk investigation data and needs about 1 GiB more memory, so use nodes of 8 GiB or more. The live news feed and a read-only Quickstart tour are separate options, and all are off by default. The approval workflows need the commercial edition. Agency on Azure has been rendered and checked, but not yet deployed to a real Azure account. What Agency adds.
Before you share the link

Signing in, and who can reach it

Two logins, both set at deploy time. Business users sign in to the Ask app with the login you chose. The admin console (/admin) and the admin API need a separate admin login (user admin), so they are never open to the internet. In the wizard, Admin console password is optional (blank = the Ask-app password) and Restrict access to these addresses takes a comma-separated list such as 203.0.113.7/32.

Leave the address list blank for a first try-out and the app is reachable from anywhere. Once you connect real data, set it to your own address or network (Search for your public IP and enter it followed by /32.): the Ask app's agent endpoint answers questions without a login using your Anthropic key, and we are fixing that in the app itself.

HTTPS is on by default and plain HTTP is closed, so passwords and answers are encrypted in transit. With no certificate supplied the stack makes a self-signed one (hence the browser warning above); to use your own, paste a PKCS12 file (base64) and its password into the deploy form and the warning goes away, provided you open the site by the name the certificate is for.

Before you click Create

Subscription prerequisites

This stack has one real regional constraint, worth checking before you pick a region in the wizard.

ResourceNeededWhere to check
AKS node VMAmpere Altra (arm64) quota, e.g. Standard_D2ps_v5Confirmed live: westus2 has clean, unrestricted availability; eastus, eastus2, and westeurope currently have none. Recheck with az vm list-skus --size Standard_D2ps_v5 --location <region> -o table before picking a different region.
AKS clusterStandard-SKU LoadBalancer supportDefault on all current AKS versions

New subscription? A new Azure subscription often starts with zero quota for the Ampere (ARM) VM families, and the deployment then stops at Azure's pre-check with InsufficientVCPUQuota before anything is created. Before you deploy, check with az vm list-usage --location <region> --query "[?name.value=='standardDPSv5Family']" -o table. If the limit is under 4, request an increase for Standard DPSv5 Family vCPUs in your region (Portal: Subscriptions, Usage + quotas). It is free; approval can take longer if it goes through a support request.

Node count and storage sizes are all adjustable in the wizard if your subscription has more headroom — or less.

Clean-room validated end to end on a real Azure subscription (westus2) — live traffic in, real questions answered out. Full engineering changelog, including everything found and fixed along the way, is in the stack's README.
Prefer the CLI

Same stack, from your terminal

Useful for scripting a deploy, or if you'd rather review the template before Portal ever gets involved.

1

Create a resource group

Pick a region with Ampere Altra availability.

az group create \
  --name omnigate-aks-rg \
  --location westus2  # confirmed live Ampere Altra availability
2

Deploy the template

Pulls the same published Bicep/ARM template.

az deployment group create \
  --resource-group omnigate-aks-rg \
  --template-uri https://github.com/thinkingsense-ai/Docker/releases/download/aks-stack-v1.0.31/azuredeploy.json \
  --parameters appPassword='<plain-text-password>' llmApiKey='<anthropic-api-key>'
Ask-app login: just type a plain username and password in the wizard — appPassword is hashed automatically during deployment, using the deployed image's own hashing utility. No local Docker, no manual hash generation. Full details in the stack's README.
After it's deployed

Check on it, or take it down

There's no need to hunt for individual resources here — an ARM deployment tracks everything it created as one resource group, the same way a CloudFormation stack or an OCI Resource Manager stack does. Two guided scripts in the stack's repo wrap the commands below; clone or download the omnigateaksstack directory to use them.

→

Check on it

Fetches credentials (installing kubectl first if it's missing — confirmed live that az aks get-credentials alone doesn't do that), checks the pods/Services, then actually curls the Ask app to confirm it's serving, not just that Kubernetes reports it as Running.

./verify.sh <your-resource-group>

Or by hand: az aks get-credentials --resource-group <your-rg> --name omnigate-aks, then kubectl get pods / kubectl get svc omnigate-omnigate-http — if EXTERNAL-IP isn't <pending>, that's your Ask app, at https://<that IP>/.

→

Tear it down

Lists what's in the resource group, asks you to type destroy to confirm, then deletes it — the entire teardown story, since everything the template created lives in that one resource group.

./destroy.sh <your-resource-group>

Or by hand: az group delete --name <your-rg> --yes --no-wait. Full details in the README's Cleanup section.

Later

Upgrading

New releases are linked on this page. To move a running deployment to one, deploy the new release's template into the same resource group with the same parameters. It takes about six minutes. Your data, settings and licence are kept. Take a backup first (the backup guide has two scripts, tested end to end), and see the upgrade guide for how to go back and what to do if an upgrade fails. From app v0.10.10, Operations → Infrastructure in the admin console shows the replicas, their versions and, for each pod, what the cluster says about it, so you can watch an upgrade (see the guide).
