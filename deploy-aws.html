Deploy OmniGate to AWS, no local tools required

A single CloudFormation stack brings up a right-sized Amazon EKS cluster, a seeded Postgres demo backend, and OmniGate itself — entirely from your browser. Nothing to build, nothing to push: the stack pulls the app from our public registry and builds its own small deploy helper into your account automatically.

Launch Stack → View the template ↓

Opens the AWS Console's Create Stack wizard, pre-loaded from our published CloudFormation template. You'll need your own AWS account — sign up if you don't have one yet.

What actually happens

Six steps, all in the browser

No Docker, eksctl, or kubectl on your machine for this path — CloudFormation and a CodeBuild project it creates do all the provisioning inside your own AWS account.

1

Sign in to your account

The Launch Stack button takes you to AWS Console sign-in, with the CloudFormation Create Stack wizard already queued up.

2

Template is pre-loaded

The template URL is already filled in from our published release — nothing to upload yourself.

3

Fill in the parameters

An Ask-app login, and (optionally) an Anthropic API key for NL2SQL — the same options as the local docker-compose.yml setup.

4

Acknowledge IAM and create

Check the "I acknowledge that AWS CloudFormation might create IAM resources" box — the stack creates roles for EKS, the node group, and the Load Balancer Controller — then click Create stack.

5

Wait for CREATE_COMPLETE

Roughly 15–20 minutes: the EKS cluster (~10 min), the node group (~3 min), a CodeBuild job that builds the stack's small deploy helper into your account (~2–3 min), then the OmniGate + Postgres Helm release.

6

Open the Ask app

The stack's Outputs tab shows AskAppUrl — open it, sign in with the login you set in step 3, and ask a real question.

Before you create the stack

Account prerequisites

Confirmed live while building this stack — worth checking first if you're on a fresh or tightly-scoped account.

ResourceNeededWhere to check
VPC / EKSA fresh VPC, an EKS cluster, and a managed node group — standard default quotas for a new accountService Quotas console, services vpc and eks
CodeBuild1 project, used once at deploy time to build the stack's deploy-helper image into your own ECRService Quotas console, service codebuild
IAMPermission to create roles, policies, an ECR repo, and a CodeBuild projectThe deploying principal needs broad-ish IAM, not just EKS access

Node instance type and group size are adjustable stack parameters if your account has more headroom — or less.

Prefer the CLI

Same stack, from your terminal

Useful for scripting a deploy, or if you'd rather review the template before Console ever gets involved.

1

Create the stack

Pulls the same published CloudFormation template.

aws cloudformation create-stack \
  --stack-name omnigate-eks \
  --template-url https://raw.githubusercontent.com/thinkingsense-ai/Docker/eks-stack-v1.0.0/resource-manager/omnigateeksstack/template.yaml \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameters ParameterKey=OmnigateAppPassword,ParameterValue=<plain-text-password>
2

Wait for it

Polls until the whole stack — cluster, node group, deploy-helper build, and Helm release — finishes.

aws cloudformation wait stack-create-complete \
  --stack-name omnigate-eks
Ask-app login: just pass a plain username and password as parameters — OmnigateAppPassword is hashed automatically during deploy, using the deployed image's own hashing utility. No local Docker, no manual hash generation. Full details in the stack's README.
