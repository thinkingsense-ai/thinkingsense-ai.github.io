What we measure, and how to read the numbers

A result is only useful if you know what it counts. This page defines the measures, shows the recorded results with their dates, and points to the walkthroughs you can run yourself.

How results are measuredRun it yourself

This is the technical guide. The overview for your team is at thinkingsense.ai.

Method

Three measures, and why only one counts

01

The query ran

The weakest signal. A wrong answer can run perfectly. We do not call this a pass.

02

It returned rows

Better, but an unfiltered or wrongly joined query also returns rows.

03

It matches the reference

Result rows compared with a known-good query, never the SQL text. Numbers are rounded to two decimals and column order is ignored. This is the one that counts.

Right rows with fewer columns than the reference are tracked as a diagnostic and are not a pass. When the reference needs columns a question never asked for, the semantic layer supplies them. The scorer is not loosened to hide that.

Recorded results

TPC-H, 22 business questions

Internal runs on TPC-H data split between PostgreSQL and object storage. Dates are shown because results change as the engine and models change. A pilot measures your own workflow and baseline.

Read the rows together. Approved queries return exact results. Free-form generation by a small model is much weaker when judged by what it returns, which is why escalation, repair and approved queries exist. Reworded questions without values are never served from a template. They ask for the values instead.
